## User Need And Core Outcome

用户每周能取得一份中文报告，了解美国加密政策与行业方向发生了什么变化、哪些人物和机构推动了变化、证据是什么，以及下一周需要关注的决策节点。报告支持逐条回到原始来源，并展示连续周度指标趋势。

初期关注美国联邦数字资产市场结构、稳定币、银行准入和代币化。人物监测必须与法案、机构和程序监测结合：职位权力、具体议题上的谈判位置和联盟行为，比发帖量更能说明影响力。工具提供可解释的政策信号，不把信号分数当作币价预测或未经校准的法案通过概率。

建议发行时间为每周一 09:00 日本时间；统计窗口为前一周一 00:00 至本周一 00:00。允许在窗口关闭后采集已公开但延迟进入数据库的材料，按事件时间归属并标记迟到记录。上述时间是待采纳的产品默认值，不是已经启动的定时任务。

## Constraints And Quality Gates

硬边界：sources/ 和用户原始 PDF 只读；只处理已公开信息或用户明确提供的材料；不绕过付费墙、登录限制或平台条款；不自动交易；不替用户发帖或联系人物；不创建付费订阅、不读取现有密钥值。任何云模型传输、付费接口和云部署都需明确批准。

首期质量目标是拟定的验收阈值，当前没有实测成绩：报告中的关键事实 100% 有原始链接和抓取时间；无可追溯证据的“已通过、已生效、已否决”结论为 0；每个高影响事件有引用片段或条款定位；采集失败不解释为“没有新闻”；历史更正保留版本。

运行目标：获准上线后连续四周形成报告或明确标记的降级报告，目标周一 09:00、延迟容忍 30 分钟。每次运行有唯一周编号和版本；同周重跑不重复发行。官方来源缺失影响关键结论时，报告显著降级，禁止输出确定性的“无变化”。

## Candidate Mechanisms

1. 先用固定来源清单采集官方文件及人物公开声明，人工标注少量事件，产出可审阅样例，验证核心结果。
2. 验证成功后，定时增量采集、合并同一事件、结构化提取、规则打分、生成报告；使用独立于个人电脑休眠的调度环境。
3. 若自动分类质量不足，保留自动采集和报告排版，由人工确认高影响事件。若社交渠道无法授权，官方来源可单独维持周报，但需声明人物发声覆盖有限。

## Recommended Route

推荐先批准 spike-only：在无新增付费、无后台持续采集、无外发的边界内，验证官方来源、身份表、事件判读和一份中文周报样例。没有可用且获准的模型时，用人工标注加确定性评分验证报告价值，不擅自启用云模型。

验证通过后，正式路线优先采用常开调度、可替换来源适配器、可替换模型和私有报告存档。调度服务和模型供应商在证据、价格与权限验证后选择；不预先假定 GitHub Actions、个人电脑或既有 AI 基础设施适合。完整开发需要更新为 full-implementation 并重新审批。

## Architecture And Technology

建议流程：人物/机构/议题目录 → 来源采集 → 原始证据及抓取状态 → 事件合并和结构化提取 → 确定性多维评分 → 周报及历史趋势 → 归档与交付状态。

候选技术为 Python、SQLite 与 Markdown/HTML 静态报告，独立适配器接入 API、RSS 和公开网页；版本锁定方式在实现前确定。首期不需要知识图谱数据库、向量数据库或多代理框架。模型只负责提取、分类和草拟说明，分数由规则计算；模型角色使用 extractor/reviewer/writer，可配置，不写死型号。保留人工待审路径，云回退须先获得传输和费用授权。

每条事件包含 event_id、主体、机构、动作、议题、发生时间、首次公开时间、首次采集时间、原始链接、证据片段定位、法案/文件编号及版本、正式状态、评分理由、待审状态。联名信和同一投票不会因涉及多人而重复计分。转载、同义报道和多渠道重复发声合并；评分依赖事件的新信息，重复引用不扩大影响。

影响权重按“人物 × 议题 × 当前角色”设置，采用有解释的序数等级，不把 A/B/C 分级直接当作连续数字。正式行为与言论分开：投票和生效文件更新政策状态；讲话、倡议、草案更新信号。主席个人讲话不自动等同机构最终决议，单一程序投票失败不自动等同法案永久终止。

初期 10 人候选：Trump、Sacks、Bessent、Tim Scott、Lummis、Alsobrooks、Tillis、Atkins、Selig、Armstrong。均须经 P5 重新核验；为避免只采亲行业立场，同时采参院两委员会两党公告、银行业和消费者保护意见。未纳入个人名录的机构事件仍然可以入库。扩展至上轮 30 人需质量和运行成本验证。

首期 8 个指标的正向定义：

| 指标 | 正向表示 | 负向表示 |
|---|---|---|
| K1 市场结构立法推进 | 实质文本共识、明确程序推进、跨党支持扩大 | 关键分歧、撤回支持、程序受阻 |
| K2 商品市场准入与管辖清晰度 | 权限边界和合规准入清晰 | 管辖冲突、准入不确定性扩大 |
| K3 证券市场合规可达性 | 注册、披露和豁免路径更可执行 | 路径收窄或关键法律不确定性增加 |
| K4 稳定币发行与支付可用性 | 清晰可执行的发行、储备、赎回和支付框架 | 不确定性、准入障碍和限制扩大 |
| K5 稳定币奖励许可空间 | 可依法提供的奖励空间扩大 | 奖励限制扩大；发行方收益与平台奖励分别标注 |
| K6 银行与托管准入 | 银行合作、托管和许可路径扩大 | 银行排斥、限制和准入障碍增加 |
| K7 资产代币化落地 | 真实发行、交易、清算安排获得明确准入 | 权利保障、发行人同意或交易安排受阻 |
| K8 政策可持续性与信任保障 | 伦理、消费者保护、金融犯罪防控与跨党机制改善 | 冲突利益、风险事件、政治反噬和可逆性增加 |

“正向”仅表示表中定义的方向，不等于好政策或资产利好。K8 在验证发现混合概念难以一致标注时必须拆分；不为了凑八维强行合成。各维独立展示，不默认生成“加密总利好指数”。

事件向量 v 的每维取 -2/-1/0/+1/+2，表示显著负向/负向/无可判变化/正向/显著正向；未知另记 null，不编码成 0。重要性、角色权重、证据等级和提取一致性单独存储；模型自报置信度不能当作实际概率。初始权重仅为待校准规则。

周内信号净变化 Δ_k = Σ(去重事件的方向值 × 议题权重 × 行动强度 × 证据系数)。短期压力趋势 T_k = Σ(事件贡献 × exp(-ln(2) × 距事件天数 / 半衰期_k))。半衰期在历史验证中校准；正式生效状态不按该公式衰减。展示本周 Δ、短期趋势、支撑与反对事件数、来源覆盖和政策状态。权重/半衰期变更时按新版本重算整段可比历史。

周报内容：一页中文摘要；8 维趋势与较上周变化；3–5 个高影响事件及证据链；人物立场/行动变化和联盟分歧；法案/规则正式状态与下一节点；信息缺口、迟到更正、人工待审项；完整来源附录。无重大事件的一周也交付报告，说明覆盖和静默依据。报告可从图表下钻到事件贡献，原始英文引文与中文解释分开。

交付建议先为私有目录中的 Markdown、HTML 和结构化 JSON；定时运行仅向用户提供完成/失败通知。通知渠道和报告目的地在正式运行审批中选择。邮件发送、Drive 上传、公开链接发布不在默认权限内。PDF 为可选后续输出，不作为首期依赖。

## Fallback, Rollback, And Exit

- Rollback trigger: 来源授权失效、关键事实错判、超出费用上限、调度漏跑或报告数据损坏。
- Last known stable state: 已验证规则版本、上次成功周报、对应事件快照及数据库备份；首次部署前稳定状态为只读人工样例。
- Reversible effects: 暂停定时任务，停用问题适配器或模型，恢复数据库备份及上一规则版本，撤销待发报告。
- Irreversible effects: 已消费 API 费用不能回滚；已送达报告不能保证收回，需要更正通知。本次编写无此类费用和外发。
- Fallback route: 保留官方材料的人工辅助周报；模型不可用时输出事实清单和待审项，评分暂停。
- Degraded user outcome: 报告覆盖或时效下降，趋势缺口明确标记，不把缺失补成中性。
- Required approval: 正式上线审批可预授权暂停、同环境恢复和用户更正通知；扩大费用、换供应商、公开发布需另批。
- Post-rollback verification: 校验事件数、版本、证据链接、周编号和评分重算；离线补跑不重复发行；恢复前确认问题已隔离。

## Spike Limits

- Time limit: 最多 4 小时实际验证工作；同一外部前置条件累计纯等待不超过 120 秒，或两次无有效进展即停止。该上限不是完工承诺。
- Cost limit: 新增付费 0；不创建订阅或动用未批准的 API/云资源。所需能力不存在则记录缺口并使用人工样例。
- Data limit: 10 人身份核验、最多 8 个官方源、50 次请求、60 份材料、40 条标注事件、一份样例报告。
- Retry limit: 每来源最多一次初始请求和一次有证据的重试；账号/权限不明、限流或条款不符即停。
- Exit condition: 时间/数据边界到达，或核心样例和 P1–P5 已形成足够证据，产出通过/失败/不确定结论和修订方案；不自动续跑。
